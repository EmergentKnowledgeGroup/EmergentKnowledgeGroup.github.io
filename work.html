01 / 09MemoryReleased · v0.2.4

ModelNumquamOblita

Local-first memory for agents that treats evidence as the contract.

View on GitHub (opens in a new tab)

What it is

MNO, as its README calls it, helps an assistant remember from real evidence instead of guessing from vibes. It imports source material, preserves provenance, builds reviewable memory, and keeps its answers tied to the evidence they came from. When the support is weak, it can abstain.

  • Imports raw source files and preserves bounded original wording for quote and provenance lookups.
  • Builds draft episode cards for human review, kept separate from reviewed truth.
  • Shows the evidence and context for why a memory was recalled.
  • Runs locally: desktop shell, HTTP runtime, or MCP server.

02 / 09Control planeSource-first

CarsinOS

Give your assistant an outcome. Follow the work. Inspect the result.

View on GitHub (opens in a new tab)

What it is

A local-first control plane for one owner running one assistant coordinator through one local instance. You hand off an outcome in plain language; CarsinOS keeps the delegated work, decisions, schedules, tools, receipts, and recovery state visible.

  • Mission Control is organized as the Glass Office: four floors called The Office, The Window, The Trenches, and The Basement.
  • Boards, plans, schedules, history, and receipts keep work inspectable after the conversation has moved on.
  • An exact dangerous action gets one concrete confirmation: the system says what will happen, and you confirm or clarify.
  • Tells a calm system from a specific incident from a state that is still checking its facts.

03 / 09Run ledgerReleased · v0.1.12

Plotkeeper

A human readable and agent understandable surface for task breakdowns and continued development.

View on GitHub (opens in a new tab)

What it is

A local, read-only run ledger and dashboard for Codex SpecSwarm. Long agent runs are difficult to inspect from one chat window, so Plotkeeper gives the operator a local control surface without becoming another writer of session truth.

  • Tails session logs by byte watermark and never edits them.
  • Shows the production goal, invariants, task board, reports, and evidence links.
  • Preserves closed runs as immutable history.
  • Won’t call a run closed until an independent review reports PASS with zero open items.

05 / 09ContinuityReleased · initial

Context Checkpoint

A state preservation system for AI coding agents that lose context on compaction.

View on GitHub (opens in a new tab)

What it is

A checkpoint script that writes relay batons, not breadcrumbs. Each checkpoint captures the step just finished, what was learned, the exact next command, validation status, and git state — so an agent that wakes up after compaction picks up the baton instead of re-investigating finished work.

  • Writes timestamped history plus a hot LATEST pointer the next agent reads on cold start.
  • The next_cmd field says exactly what to run next: no re-investigation, no re-discovery.
  • Multiple agents checkpoint independently with --track.
  • Standard-library Python: 426 lines, no external dependencies.

At a glance

Status
Initial release
License
MIT (per the README)
Built with
Python 3.9+, stdlib only
Output
Markdown and JSON checkpoints

Built out of necessity. Per the README, it turned 2,065 context deaths into 2,065 clean handoffs.

STARSHAPE Observatory

A shared semantic sky drawn by agents.

Open the live sky (opens in a new tab) GitHub (opens in a new tab)

What it is

A public semantic sky built for the OpenAI WebMCP Challenge. A browser agent receives 24 server-selected concepts, chooses exactly six, and commits a connected constellation of five to eight edges. You watch it happen in the page, and the accepted trace becomes part of the shared sky.

  • Three WebMCP tools: observe_sky, trace_constellation, and read_sky.
  • Accepts no free-form prose, identity, account, or model label. Only the structured choice.
  • Keeps immutable trace receipts.
  • Does not claim to expose model internals or measure how an AI thinks.

09 / 09Code mapPublic · v0.1.1

Faultline

A geological survey of your codebase.

Open the live map (opens in a new tab) GitHub (opens in a new tab)

What it is

Faultline by EKG reads a codebase and draws what it does on one map: every decision, every wait, every way it can end. Programs draw it, not a model, so the same code gives the same bytes. People get one HTML file to zoom, hover, and walk; agents get the same map as short text, with a token cap on every answer.

  • Draws a box or road solid where a type checker or the flow graph decided it, and dashed with a ? where the tool only matched a name. Open it and the panel says why.
  • At every failure and refusal in the code, asks who finds out: a person, the calling code, a log, or nobody. When the code doesn’t say, the page says “not known from the code.”
  • An agent helps in two places only: answering the questions the tool flagged, and writing marked words on top. It can’t add a box or a road.
  • Reads your code as text and never runs it, and writes its map into a .faultline folder (or one you name with --project). After install it runs offline, except for Python setup, which downloads one file and checks its hash.
